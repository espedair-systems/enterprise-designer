In the Unified Modeling Language (UML), there are 14 official types of diagrams. These are strictly divided into two main categories: Structural Diagrams (which capture the static architecture of the system) and Behavioral Diagrams (which capture the dynamic workflow and interactions). [1, 2, 3] 


## Behavioral Diagrams
Behavioral diagrams explain what happens in the system and illustrate how data, users, and objects interact over time. [1] 

* 
* Use Case Diagram: Models high-level user interactions and functionality requirements of the system.
* Activity Diagram: Works like an advanced flowchart to show the step-by-step logic and operational workflow.
* State Machine Diagram: Shows the various states an object goes through in response to internal or external events.
* Sequence Diagram: Details how objects interact with one another chronologically using message lines.
* Communication Diagram: Focuses on the structural architecture of objects that pass messages back and forth.
* Interaction Overview Diagram: Provides a high-level view combining activity diagrams with parts of sequence diagrams.
* Timing Diagram: Focuses specifically on execution time constraints and state changes over a strict timeline. [1, 4, 7, 8, 9, 10] 
* 

If you are trying to design a specific feature, let me know what you are building or which aspect of the system (e.g., database structure, user logic, workflow) you want to map out so I can recommend the exact diagram you need.



## Structural Diagrams
Structural diagrams show the "things" in a system, detailing its components, relationships, and physical infrastructure. [1] 

* 
* Class Diagram: Shows classes, attributes, methods, and their relationships. It is the most common UML diagram.
* Object Diagram: Captures a specific snapshot of instances at a particular moment in time.
* Component Diagram: Illustrates how structural software components pieces together and depend on each other.
* Deployment Diagram: Maps out the physical hardware architecture and where software artifacts are deployed.
* Package Diagram: Groups related system elements together into packages to show macro-dependencies.
* Composite Structure Diagram: Explains the internal micro-structure of a class or classifier.
* Profile Diagram: Extends standard UML models for specific domains using custom stereotypes. [1, 2, 4, 5, 6, 7]
